Risk log: what actually happened

Three of four risks occurred. All three were closed.

R1 · SCORE 12 · CLOSED

Password model not learning patterns

Happened: the model couldn’t learn patterns, which caused a predictability issue.

Action: changed the data set and optimised it for the higher-order approach.

R2 · SCORE 15 · CLOSED

URL model accuracy under target

Happened: accuracy missed the 93%+ target.

Action: retrained the model with more data.

R3 · SCORE 8 · CLOSED

Phishing model file corrupted

Happened: the model couldn’t fetch features from a website.

Action: restored from the Google Drive backup and adapted the older version to the current Python version.

R4 · SCORE 4 · NOT OCCURRED

Python version mismatch with backend

Mitigation: version requirements tracked through development.

Takeaway: the mitigation column in the risk log was written before the problems arrived, so each fix was already half-decided.

Lessons I wrote down

From the final report.

TEST EARLIER

Start testing as soon as systems are ready.

PROTECT THE END

Reserve time for final checks and approvals.

WATCH DEPENDENCIES

Review them regularly and chase important tasks before their deadlines.
